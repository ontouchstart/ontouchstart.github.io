Here is the explanation of the failure and how it can be fixed at the system level:
The Problem: "Task-Based Execution"

The error message MCP error -32600: Tool "simulate-research-query" requires task-based execution means that this specific tool is designed to be streamed.

Instead of a simple "Input →→ Output" flow (which is how I call most tools), this tool is designed to:

    Send a starting signal.
    Stream multiple "progress" updates (e.g., "Searching...", "Analyzing...", "Synthesizing...").
    Potentially pause and ask the user for more information (elicitation) mid-way through.

Because I am currently calling it as a standard single-turn tool, the server is rejecting the request because it doesn't know how to "stream" the results back into a single response.
The Fix (For the Developer/Client)

To "fix" this, the client (the application running this conversation) needs to use the Task API instead of the standard Tool API.

The error message actually provides the solution:

    Use client.experimental.tasks.callToolStream() instead.

To implement this fix, the developer needs to:

    Identify the simulate-research-query tool in the client configuration.
    Move it from the standard tools list to the experimental_tasks handling logic.
    Update the UI to handle a stream of messages rather than a single final response.
